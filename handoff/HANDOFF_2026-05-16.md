## Jinc Accumulation Follow-Up

`redu17` was the first jinc run with the timers:

- Citlali `v4.0.0-357-gfe862127`
- `method: jinc`
- `parallel_policy: omp`
- `n_threads: 15`
- `n_noise_maps: 25`
- full process time `10m8.452688525s`

The jinc timer split showed that setup and merge are negligible:

- `populate_maps_jinc accumulate`: 124 calls, sum `5802.822082s`
- `populate_maps_jinc setup`: 124 calls, sum `5.345762s`
- `populate_maps_jinc merge`: 124 calls, sum `3.847349s`

Validated serial code change:

- For the standard non-direct noise path where `nmb == omb`, serial jinc now
  accumulates each detector's gridded signal contribution into a local template
  and scales that template into each noise realization.
- This avoids re-splatting the same jinc footprint for every noise realization
  when a simple work estimate says the detector template should be cheaper.
- The old per-sample noise path remains for direct accumulation, coadd-noise
  cases, and cases where the template estimate is not favorable.

`redu18` validated this serial jinc change:

- Citlali `v4.0.0-358-gb0ba0c58`
- same generated config as `redu17`
- full process time `5m40.968873354s`
- `populate_maps_jinc accumulate`: 124 calls, sum `2046.609612s`
- zero `coverage_bool_I` mismatches in checked FITS maps
- largest signal-map max absolute difference `2.66e-15`
- largest `noise_variance_I` max absolute difference `3.0e-15`
- largest checked FITS max absolute difference `3.41e-13` in `coverage_I`

Validated `redu24` timing run:

- The same detector-template idea has been ported to
  `populate_maps_jinc_parallel` for detector-grouped OMB noise maps.
- This is the standard beammap jinc path.
- The parallel optimization is deliberately narrower than the serial one:
  coadd noise and non-detector grouping remain on the existing per-sample
  accumulation path.

## Naive Noise Merge Follow-Up

`redu19` used Citlali `v4.0.0-360-gcb252bdf` with the same generated config as
`redu14`/`redu15`:

- `method: naive`
- `n_noise_maps: 25`
- `n_threads: 15`
- full process time `3m38.546494986s`

Product comparison against the `gw_dev` control `redu14` was roundoff-clean:

- zero coverage-mask mismatches in all checked FITS maps
- largest signal-map max absolute difference `3.55e-15`
- largest checked FITS max absolute difference `2.84e-14` in coadd
  `noise_variance_I`

The new post-map timers showed that normalization, PSD, histogram, median
diagnostics, and empirical noise products are negligible for this small map.
The more important result was the naive merge timing:

- `populate_maps_naive merge`: 124 calls, sum `47.663736s`
- merge timer wall union `46.693246s`

This means the merge timer mostly measures serialized work, not lock waiting.
The old naive noise merge added the full coadd noise cube once per scan.

The first attempted fix, `c9847b4c` / `redu20`, tracked individual touched
pixels and merged only those pixels. It was numerically clean against `redu19`
and `redu14`:

- zero coverage-mask mismatches in all checked FITS maps
- largest checked FITS max absolute difference `2.84e-14`

It was not a speed win:

- full process time `3m38.485279408s`
- `populate_maps_naive merge`: 124 calls, sum `48.472683s`
- `populate_maps_naive accumulate`: 124 calls, sum `306.260351s`

The second attempt, `e5494b12` / `redu21`, used monotonic touched rectangles
instead of per-pixel hash bookkeeping. It was also numerically clean:

- zero coverage-mask mismatches against `redu20`, `redu19`, and `redu14`
- largest checked FITS max absolute difference `2.84e-14`

It improved the targeted merge timer but not the whole reduction:

- full process time `3m42.633053969s`
- `populate_maps_naive merge`: 124 calls, sum `42.595539s`
- `populate_maps_naive accumulate`: 124 calls, sum `267.652397s`
- `populate_maps_naive total`: 124 calls, sum `311.417542s`

Interpretation: the bounded block merge is safe and helps the merge path, but
this compact map does not expose a clear end-to-end win.

Validated code change, `ad6591f4` / `redu22`:

- `populate_maps_naive` now builds a sparse nearest-pixel weighted-signal
  template for each detector and scales that detector template into each noise
  realization afterward.
- This removes the `n_noise_maps` loop from the per-sample hot path while
  preserving the final resident noise cube and output format.
- This directly targets the `populate_maps_naive accumulate` timer in the same
  `148481`, naive, 25-noise-map standard run.

`redu22` used Citlali `v4.0.0-363-gad6591f4`; its generated config was

Previous unvalidated code change, now validated by `redu21`:

- `populate_maps_naive` still avoids copying the destination noise cube into
  scratch.
- Instead of per-pixel hash bookkeeping, each scratch noise map keeps a
  monotonic touched rectangle.
- Newly exposed rectangular bands are zeroed before accumulation, and the final
  touched rectangle for each map/noise plane is merged back as contiguous Eigen
  blocks under the existing mutex.
- This should matter most for maps where the configured map area is much larger
  than the scan/array footprint, without the scattered `unordered_set` overhead
  seen in `redu20`.
