Jinc rationale:

- The scalar tiled accumulator is not a good jinc primitive because jinc splats
  dense footprint blocks, not single pixels.
- If jinc benefits from tiling, it should be a block-aware accumulator or a
  precomputed sample-footprint plan, not per-pixel tile hash lookups.
- Added coarse jinc timers so the next Unity run can identify the actual hot
  section before larger changes:
  - `populate_maps_jinc total`,
  - `populate_maps_jinc setup`,
  - `populate_maps_jinc accumulate`,
  - `populate_maps_jinc merge`,
  - `populate_maps_jinc_parallel total`,
  - `populate_maps_jinc_parallel accumulate`.
