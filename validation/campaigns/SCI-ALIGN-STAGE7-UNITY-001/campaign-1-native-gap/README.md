# SCI-ALIGN Stage 7 Unity Campaign 1 — native-gap Science

## State and purpose

This package is **prepared but not authorized for launch**. It defines only
the first owner-run Stage 7 campaign: one small Science observation with a
fresh verified matched-v2 relation and native gaps. It does not accept Stage
7, change the canonical Science kit, or authorize production use.

The activation implementation is exact commit
`36f6ada25d06f2236dfcd279d53c6afc40298cb1`, tree
`40099545347326aed03df7be22bcc7cfe74e0e7d`. Campaign setup and evidence must
retain that implementation identity even when later documentation-only
descendants are used to carry this package.

## Campaign configuration

`99_zzz_sci_align_stage7_native_gap.yaml` is a campaign-only final numbered
overlay. Copy it into a newly generated **Science refactor** reduction after
TolProj setup. Do not edit the canonical files under `config/tolteca/v2` and
do not mix this overlay with a legacy config family.

The overlay selects naive mapmaking, disables unsupported global/iterative
operations and extra products, and disables the Science FIR because its
nonzero loaded outer context is outside the candidate domain. It deliberately
retains supported despiking, network-local step/impulsive diagnostics,
flux calibration, one `nw` standard-PCA group, and full weighting.

The final runtime source order must end with:

```text
99_science_expert_overrides.yaml
99_zz_tolproj_submission_runtime.yaml   # when generated by TolProj
99_zzz_sci_align_stage7_native_gap.yaml # always final
```

Run the frozen merge preflight from the Citlali repository root before any
submission:

```bash
CAMPAIGN=validation/campaigns/SCI-ALIGN-STAGE7-UNITY-001/campaign-1-native-gap
REDUCTION=/absolute/path/to/the/new/science/reduction
PYTHON_BIN=/absolute/path/to/the/TolTECA-environment/bin/python
cp "$CAMPAIGN/99_zzz_sci_align_stage7_native_gap.yaml" "$REDUCTION/"
"$PYTHON_BIN" "$CAMPAIGN/preflight.py" \
  --mode-dir "$REDUCTION" \
  --merged-out "$REDUCTION/sci-align-stage7-c1-merged.yaml" \
  --report-out "$REDUCTION/sci-align-stage7-c1-config-report.json"
sha256sum "$REDUCTION/sci-align-stage7-c1-merged.yaml" \
  "$REDUCTION/sci-align-stage7-c1-config-report.json"
```

The preflight must say `config_ready_observation_checks_pending`. Inspect the
merged YAML and JSON report before launch. That status means the static config
is ready; it does **not** claim the observation has been admitted.

## Owner-supplied observation gate

Before launch, the owner must identify one small Science observation for which
all of the following are true:

1. the observation config points to an absolute fresh matched-v2
   `manifest.ecsv`, not a baseline bundle or legacy APT;
2. the candidate CLI returns `status:"ok"` for `validate-bundle-v2` and the
   verified bundle's raw-source identities match the selected files exactly;
3. all matched native alignment and pointing carriers are present;
4. duplicate-tone detection realizes one value per admitted detector and all
   values are zero; and
5. every realized scan has outer-context bounds equal to its science bounds.

Validate the bundle with the same executable that will run the reduction:

```bash
ROOT_MANIFEST=/absolute/path/to/matched.apt-v2/manifest.ecsv
printf '%s\n' "{\"protocol\":\"citlali-canonical-apt-protocol-v2\",\"request_id\":\"sci-align-stage7-c1-preflight\",\"operation\":\"validate-bundle-v2\",\"payload\":{\"root_manifest\":\"${ROOT_MANIFEST}\"}}" \
  | build/bin/citlali --canonical-apt-contract-v2 \
  | tee sci-align-stage7-c1-bundle-validation.json
```

If duplicate tones or nonzero outer context are reported at observation setup,
stop. Select or prepare a conforming input; do not weaken the candidate guard.

## Evidence to retain

Before submission, capture source commit/tree, CLI version, binary SHA-256,
KIDs identity, the numbered-source inventory from the config report, merged
YAML and its SHA-256, bundle-validation response, root/component identities,
and exact raw-source paths/byte counts/SHA-256 values. Also retain the Slurm
command, resources, environment, and complete stdout/stderr.

After a successful run, retain the complete native provenance sidecar,
deterministic product index, product inventory, log, exit status, and
Unity-side byte count/SHA-256/header inventory for every large FITS product.
The native sidecar must cover every expected scan and establish measured-only
sample identity with no synthesized or gap-bridging occurrence.

Stop on a missing scan/product, missing or partial native lineage, unexpected
error-level log record, unexplained detector/flag change, or any evidence that
the legacy RTC/PTC route also executed. Do not advance to Campaign 2 until
Campaign 1 evidence has been downloaded (large FITS may remain on Unity) and
reviewed.
