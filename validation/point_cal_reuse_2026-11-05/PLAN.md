## Execution and ownership

The normal configured weighted Python route launches one native observation
process at health. A digest-bound development descriptor selects each stage,
whose path is derived from its ordinal beneath the original work directory.
A private reply pipe associates completion with the submitted descriptor.
Separate logs capture native diagnostics. Python owns feedback and early
stopping, and finishes or aborts and joins the session before final publication.
Finish has a 30-second teardown deadline once the scientific work has been
acknowledged. Session cleanup reaps the child and closes both streams even
when a peer dies before the next write. Stage descriptors, pass requests,
effective config, frozen health, model FITS bytes and feedback/bundle records
are interpreted from the same bytes that satisfied their declared digests.
Native standalone requests, v1, comparison and recovery retain individual
stage/replay entry points.

Health prepares checked CAL samples, eligibility, source masks, scheduled
coordinates, segment and detector associations. Temporary parse trees, native
clocks and telescope trajectories are released after their numerical products
are realized. The original CAL ledger and compact authenticated APT transport
identities belong to this observation. The sorted network and optical arrays
are read-only to science consumers. Every cycle requires its original ordered
network bindings, effective-config generation and frozen health. Its model,
weights, residuals and output plan are fresh. Original CAL bytes and complete
APT inventories are rechecked before reuse and before publication, along with
the current pass's request and model bindings. A different observation starts
another process. Additional in-memory storage while Python computes feedback
is an intentional, measured resource tradeoff.
