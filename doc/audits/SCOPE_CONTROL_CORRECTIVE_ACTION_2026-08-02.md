# Scope-control corrective action

Policy ID: `FRAMEWORK-SCOPE-001`

Status: active for future dispatches and future phases

Authority: project-owner approval, 2026-08-02

## Purpose and boundaries

This corrective action prevents a bounded Citlali task from accumulating
unapproved local execution, generalized engineering controls, or validation
machinery whose scientific need was never established. It adds coordinator
checkpoints; it does not alter an approved scientific contract, an active
task, a frozen artifact, application code, a package status axis, Unity access,
or `FRAMEWORK-NUM-001` costly-study controls.

## Triggering examples

### SCI-ALIGN-001 local validation

The ALIGN repair dispatch allowed naturally required local Pointing and
Beammap reductions without making Unity the default reduction-evidence lane or
requiring a local-only rationale. The task therefore used local reductions for
compatibility evidence where the project owner prefers human-run Unity
reductions unless locality is explicitly justified. The running reduction was
allowed to complete; this record neither invalidates it nor changes its
evidence limits. Future local Citlali reductions require explicit authority.

### SCI-MAP-001 Unity preparation

The MAP evidence-preparation dispatch combined the desired Unity input/run
package with generalized capture, provenance, resource, verifier, schema, and
independent-review machinery. The task expanded into a 41-file uncommitted
draft and repeated control remediation. That work exceeded the operational
need to prepare a human-usable Unity transfer/run package. The preserved draft
is not discarded by this action; its successor is constrained to a minimal
packaging scope under a separate coordinator direction.

## Required controls

1. Before substantive work, a task returns a scope checkpoint naming allowed
   paths and deliverables, execution authority, named tests/evidence,
   delegation/review authority, first viable artifact, and next return point.
2. Unity is the default reduction-evidence lane. A local Citlali reduction is
   prohibited unless the dispatch states its bounded purpose and local-only
   rationale.
3. A task returns before introducing a new executable helper, schema, wrapper,
   verifier, validation campaign, delegation, independent review, or
   scientific/operational interpretation beyond its checkpoint.
4. The coordinator reviews the scope checkpoint, the first viable artifact,
   and any proposed costly or local execution. No perfection pass or
   generalized control system is implied by a first viable artifact.
5. Scope-change records belong in the coordinator ledger's phase dispatch
   history. They name the requested expansion, scientific/operational reason,
   permitted paths, approving authority, and replacement stop rule.

## Verification

The policy is realized in the audit README, Audit Manager instructions,
package prompt template, and machine-readable ledger vocabulary. Future
dispatches must carry the required checkpoint fields. Existing tasks retain
their frozen authorities unless a later explicit coordinator direction says
otherwise.
