### RA-002 — closed

The source-mask identity is captured at its realization site. For each RTC
scan, the code resets prior telemetry, constructs the source-protection mask,
records its exact shape, masked-sample count, and deterministic digest over
the matrix elements in declared storage order, and only then moves the same
mask into the despiker. Observation realization fails closed if the required
scan identity is unavailable and aggregates the per-scan identities into the
versioned compact realization.

Notch realization records the actual ordered operations after construction or
application. Each entry carries its stage, optional detector index, exact
binary64 center and width representations, and zero-phase state. The stages
distinguish configured TOD notches, fixed line-audit pre-notches,
shared-dynamic line-audit pre/post notches, and per-detector post-notches.
Configuration facts separately retain configured centers, widths/Q values,
counts, and fixed-notch vectors; realized facts bind the ordered applied
operators. Per-scan state is synchronized and reset, and the observation
identity fails closed on missing scan telemetry.

`Cleaner::remove_eig_values` now returns the final removal limit after the
actual priority and clamp sequence: forced index when present,
standard-deviation-derived limit otherwise when enabled, configured limit
otherwise, then eigenvector-column and Spectra detector-count bounds. Both
ordinary and correlated-group PTC paths record that returned value as
`applied_cut`. The adaptive precomputed-eigenvector path records the same
column-clamped cut that `apply_cut` consumes. Requested/configured values
remain distinct from actual application.

Disposition: **closed**.

### RA-005 — closed

The new `publish_required_observation_outputs` helper is production code and
is called by `write_observation_outputs_and_accumulate`. It invokes all
required raw/coadd-or-noncoadd writers before mapmaking, pointing, or Beammap
observation completion. An exception from any required writer therefore
propagates before completion can publish success.

The JINC writer validates complete processing provenance before output and
generates joins from the FITS files, HDUs, and planes it actually writes. The
Lali output implementation finalizes and closes its file vectors within the
required writer call, so finalization failures also precede observation
completion. On success, `complete_mapmaking_observation_if_available` copies
the writer-populated JINC realized state into the execution-plan observation
and marks outputs complete. `mapmaking_provenance_node`, used by the CLI
sidecar writer after run completion, serializes those same copied joins.

The post-check test begins with complete processing provenance and no joins,
then forces a required writer failure by removing the formal-support plane.
The writer has already begun HDU work when the failure occurs. The exception
leaves product joins empty, observation outputs incomplete, observation JINC
state unavailable, and the serialized observation without realized success.
The paired successful invocation verifies exact equality of every
writer-generated join field in the serialized observation record. This is the
nonduplicative end-to-end seam that the second-successor re-audit found
missing.

Disposition: **closed**.
