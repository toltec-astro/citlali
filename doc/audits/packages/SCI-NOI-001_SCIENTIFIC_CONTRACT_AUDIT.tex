\section{Executive disposition}
\label{sec:disposition}

\textbf{Verdict: amend.  Contract status is proposed; implementation status
is nonconformant with material conforming subcontracts; validation is
incomplete; production status remains existing-use-only.}  This audit does
not authorize a repair, a new estimator, a realization-count default, a
reduction, an evidence request, or production use.

The governing implementation constructs finite signs in $\{-1,+1\}$ and, on
the accepted ordinary Stokes-$I$ naive lane, applies each sign to the fixed
post-RTC/PTC sample value at the map contribution point.  The realization
uses the same detector/sample eligibility predicate, positive coefficient,
projection, map normalization support, and observation coadd coefficient as
the science map.  These facts conform structurally to \rthree{1}{eq:fixed-state},
\rthree{4}{eq:sign-operator}, \rthree{10}{eq:unit-map-contributions}, and
\rthree{33}{eq:fixed-coadd}.  JINC contains the corresponding sign
multiplication and shared gridding path, but every JINC conclusion in this
report is conditioned on \path{SCI-MAP-002}.

The package does not close for six central reasons.  First, the fixed
\texttt{boost::random::mt19937} seed 5489 is recreated for every ordinary
observation pipeline invocation without observation, iteration, array,
network, detector/channel, or realization namespaces.  Equal-shaped
observations therefore reuse the same pseudorandom prefix, so the
cross-observation term in \rthree{36}{eq:coadd-covariance} is not the target
independent-observation law.  Second, the Beammap reset path regenerates and
overwrites every PTC sign array once per active map slot, making the retained
assignment depend on active-map/pass history rather than a named realization
key.  Third, current provenance records engine, fixed seed, coarse scope,
configuration, and inferred counts, while the science-map digest verifies
the final map bundle; neither record provides the compact lossless
reconstruction facts required by \rthree{49}{eq:rng-key-map}--
\rthree{50}{eq:realization-identity}.

Fourth, the ordinary non-fruit path randomizes the entire cleaned sample
$x=s+n$, so deterministic astronomical signal is present in individual
realizations and their second moments, as required by
\rthree{21}{eq:fixed-realization-decomposition} and
\rthree{26}{eq:signal-second-moment}.  A negative source in a persisted
realization is therefore produced directly by the
\path{MapBuffer::noise} $\rightarrow$
\path{add_noise_realization_image_hdus} path; the relevant FITS HDU is
\path{signal_<map><realization>_<stokes>} in a raw or filtered noise file.
This identifies the literal anti-source-capable product without validating
any variance or S/N estimator.  Fifth, a Wiener/convolution filter reuses the
same template, denominator, edge window, and core transform for every
realization, but the science signal alone receives an affine edge-background
fill.  The science and realization preprocessing operators are not identical
when that background is nonzero.  Sixth, an enabled realization count of zero
is accepted by configuration validation although downstream diagnostics and
required empirical-product publication require a positive stack.

The code then computes a mean-subtracted $1/N$ pixel stack variance, a global
empirical rescaling of the map coefficient, pixel and point-source S/N,
median realization RMS, averaged PSD/histogram products, and feedback gates.
The empirical rescale occurs before observation coaddition or filtering and
therefore couples the realization stack into later operators as the interface
fact in \rthree{37}{eq:data-derived-coadd}.  All finite-$N$ normalization,
variance/weight calibration, S/N, significance, threshold, feedback,
aperture-uncertainty, and production-count decisions remain exclusively with
\path{SCI-NOI-002}.

\section{Fixed state, sign insertion, and eligibility}
\label{sec:insertion}

\srclabel{} The ordinary Lali and Pointing generators allocate a sign array
before loading each RTC scan.  RTC processing copies that array unchanged to
its output.  The sign is not applied to the timestream there.  It is applied
later in the mapmaker as
\begin{equation}
  \texttt{noise\_value}=
  \texttt{sign}\,\texttt{sample\_signal}\,\texttt{coefficient},
  \label{eq:implementation-insertion}
\end{equation}
after RTC/PTC, learned exclusions, fruit-state handling, and weight
resolution for that pass.  Equation~\eqref{eq:implementation-insertion} is
the implementation of \rthree{1}{eq:fixed-state},
\rthree{2}{eq:map-operator}, and \rthree{4}{eq:sign-operator}.

\srclabel{} On the ordinary naive lane, a detector contributes to science and
every realization only when the observation-scoped detector/channel column
has APT flag zero, the sample flag is false, the active map is admitted, the
projection is finite/in bounds, the coefficient is finite and positive, and
the contributing sample is finite.  Flagged payloads are not inspected.
Eligible non-finite projection/sample/coefficient values fail with an
exception; out-of-bounds map samples are skipped.  The same projection,
coefficient, and sample are used for the signal and all signs.  Noise values
are staged and committed under the same aggregate preflight.

\conditionedlabel{} The JINC functions also use the same detector/sample
predicate for science and realizations, the same JINC block, and the same
positive coefficient.  Their visible legacy predicate silently skips a
non-finite sample rather than using the naive fail-closed rule.  Support,
normalization, response, validity, and sequential/parallel admissibility are
therefore not promoted here; they remain conditioned on \path{SCI-MAP-002}.

\srclabel{} Map normalization applies the same numerical support mask and the
same denominator to the signal, kernel, and every realization.  It zeros each
companion outside support and requires all declared realization companions to
be finite before marking a science-valid pixel.  These facts implement the
common propagation requirement of \rthree{3}{eq:state-lifecycle} and the
validity part of \rthree{50}{eq:realization-identity}.  Whether upstream flags
and exclusions are scientifically correct remains conditioned on
\path{SCI-VAL-001}; whether the cleaned sample covariance and coefficient are
scientifically correct remains conditioned on \path{SCI-PTC-001}.

\subsection{Target law and finite stack}

\srclabel{} Every entry is \texttt{2*uniform\_int(0,1)-1}; the target marginal
is a finite Rademacher sign, satisfying \rthree{6}{eq:unit-sign-moments} as an
algorithmic target.  There is no balancing, orthogonal assignment,
duplicate rejection, complement rejection, empirical-moment check, or
effective-unique count.  Thus \rthree{13}{eq:within-realization-balance} is
not enforced, while the cardinality and collision limits in

remain operative.  Individual finite stacks can have nonzero empirical sign
mean and correlation as in \rthree{40}{eq:empirical-sign-mean}--
\rthree{41}{eq:empirical-sign-correlation}.

\subsection{Seed, namespaces, collisions, and scheduling}

\srclabel{} The engine is \texttt{boost::random::mt19937}; the only seed is
the compiled unsigned constant 5489; there is no configured master seed or
key derivation.  Each Lali/Pointing \path{engine.pipeline} invocation creates
a new engine.  The reduction observation loop invokes that pipeline once per
observation and again on later fruit iterations.  Therefore the same draw
prefix repeats across observations/iterations having the same preceding
shape and scan/channel ordering.  Observation number, array, network,
observation-scoped channel identity, and realization ID do not enter the RNG
state.  This is a direct nonconformance to \rthree{49}{eq:rng-key-map} and
\rthree{50}{eq:realization-identity}.

\inflabel{} A fixed seed provides repeatability only for the exact build,
Boost/Eigen behavior, scan order, detector/channel order, matrix shape, and
control-flow history.  It does not provide independent observation keys.
Because a given realization ordinal is coadded with the same ordinal from
each observation, Eq.~(36) can retain cross-observation sign terms rather than
the independent-observation target.

\srclabel{} Ordinary signs are drawn in the sequential GRPPI generator before
the farm, so assignment order is invariant to the downstream sequential or
OpenMP policy.  Beammap signs are also fixed before detector/scan map
population.  The map arithmetic can still differ within the separately
approved MAP numerical-equivalence policy, and JINC remains conditioned on
\path{SCI-MAP-002}.  Existing tests verify the compiled default MT sequence,
typed configuration, count arithmetic, map propagation with supplied signs,
and provenance serialization; they do not test generated sign balance,
$Q_\epsilon$, observation namespace separation, duplicates/complements,
Beammap reset identity, or exact sequential/OpenMP sign reconstruction.

\section{Requested, effective, realized, and provenance state}
\label{sec:state}

\subsection{Lifecycle and cardinality}

\srclabel{} The typed request contains
\texttt{enabled}, \texttt{n\_noise\_maps}, \texttt{randomize\_dets},
\texttt{write\_realizations}, \texttt{products.enabled}, and
\texttt{products.apply\_empirical\_weights}.  If mapmaking or the request is
disabled, the effective plan disables noise and sets its effective count to
zero without mutating the request.  The effective count and randomization
mode are adapted one way into observation and, when enabled, coadd buffers.
The count is reduction-global rather than observation-resolved; map counts
are observation-resolved in the mapmaking plan.

\srclabel{} A completed realized record is inferred only after the entire
mapmaking/output lifecycle succeeds.  It records maps per scientific map,
observation/coadd map and realization cardinalities, empirical product-map
count, configured realization-image write count, and a boolean output
completion state.  It does not record completed realization IDs or partial
success.  A required write or product failure throws and prevents final noise
provenance publication; this is fail-closed but supplies no partial recovery
record.  The counts are plan-derived rather than a digest of observed files.

\srclabel{} Configuration validation permits
\texttt{enabled=true,n\_noise\_maps=0}.  Buffer allocation then creates a
nonempty map list whose tensors have depth zero.  The map PSD/histogram code
tests only whether the list is nonempty, performs zero realization
iterations, and then accesses the absent averaged-noise result.  If empirical
products are requested, their calculation returns without creating required
planes and the FITS writer fails the required inventory check.  A positive
count is therefore an unstated operational precondition.  Selecting its
production value, including whether shipped counts 1, 5, or 10 are adequate,
belongs to \path{SCI-NOI-002}.  A count of 64 is only an optional
resource-admitted validation tier.

\subsection{What provenance does and does not establish}

Positive controls are material:

\begin{itemize}[leftmargin=*]
  \item \path{noise_products_provenance.yaml} atomically records requested and
        effective config, the engine string, seed 5489, policy string, coarse
        generator-scope string, and realized cardinalities.  Write failures
        propagate.
  \item The SCI-MAP raw-parent digest hashes the admitted bundle identity,
        signal, coefficient, kernel when present, every final realization
        map plane, support/validity products, and realized map facts.  It is
        used to verify observation/coadd admission and filtered raw-parent
        identity.
  \item Realization companions receive stable ordinal names
        \path{noise_realization_<r>_I}; observation files carry observation
        identity, and coadd admissions carry ordered observation IDs.
\end{itemize}

These are verification and product-join facts, not a lossless sign
representation.  The records omit the RNG/library version, assignment-policy
version, observation/reduction-iteration namespace, scan/coherence partition,
stable realized channel-order digest, active Beammap pass/map sequence,
completed realization IDs, assignment digest, current-versus-residual
ensemble mode, and a join from those facts to each realization product.
The fruit restart checkpoint contains no noise RNG or assignment state.  A
consumer cannot reconstruct exact signs from the digest alone, and the sidecar
does not contain enough facts to reconstruct them unambiguously.  The closure
contract is proportional: existing deterministic ordering plus compact
versioned key/partition/completion facts and a digest are sufficient; dense
per-sample identities, persisted sign vectors, and dense $N\times N$ sign
correlation matrices are not required.  If reconstruction cannot be supplied,
the gap must remain classified rather than repaired with dense storage by
default.

\section{Map, coadd, filter, and residual propagation}
\label{sec:operators}

\subsection{Naive and JINC mapmaking}

\srclabel{} The ordinary naive path forms the signal contribution
$q_jx_j$ and each realization contribution $\epsilon^{(r)}_{g(j)}q_jx_j$
under one predicate, then normalizes both by the same map denominator and
support.  Its requested sequential and parallel entry points both dispatch
the same ordinary Stokes-$I$ contract function.  This realizes
\rthree{2}{eq:map-operator}, \rthree{10}{eq:unit-map-contributions}, and
\rthree{15}{eq:current-ensemble} for the accepted MAP lane.

\conditionedlabel{} Both visible JINC functions multiply the same weighted
sample by the same sign and JINC block used for science.  The ordinary JINC
caller can be scan-parallel; the detector Beammap caller uses the explicitly
parallel function.  The latter is map-disjoint only under its detector-group
caller invariant.  These are source reachability facts, not approval of JINC
response/support/normalization/validity or numerical equivalence.  All JINC
uses remain conditional on \path{SCI-MAP-002}.

\subsection{Fixed-weight observation coaddition}

\srclabel{} Each admitted observation realization is multiplied by the same
realized observation coefficient used for signal and added into the same
centered coadd pixel.  Normalization support is checked before signal,
coefficient, kernel, realization, or retained exposure is evaluated.  The
coadd cube must match the observation count and shape, and all realization
companions must be finite.  Final coadd normalization divides signal, kernel,
and every realization by the same accumulated coefficient.  This implements
\rthree{33}{eq:fixed-coadd}--\rthree{36}{eq:coadd-covariance} conditional on
the accepted MAP interface.

\srclabel{} Raw observation empirical products are calculated before coadd.
When configured, \path{calc_noise_products} replaces the observation
coefficient plane by one globally rescaled from the realization stack, then
refreshes map support provenance.  The coadd consumes that realized plane.
The coupling is exactly the interface fact in
\rthree{37}{eq:data-derived-coadd}; whether the scale is a valid weight is not
decided here.  Because ordinary observations also repeat their sign sequence,
the fixed-weight cross-observation covariance cannot be evaluated under an
independence assumption without additional evidence.

\subsection{Filtering}

\srclabel{} For each map, the filter builds one template, filters science, and
retains the realized denominator.  Every realization then uses the same
template, denominator, edge window, and convolution/Wiener numerator rule.
OpenMP parallelizes realization indices but writes disjoint tensor chips.
This is a positive conditional implementation of
\rthree{38}{eq:fixed-filter}--\rthree{39}{eq:filter-propagation} after the
filter state is frozen.

There is one bounded exception.  With edge guard enabled, science is replaced
before filtering by
\begin{equation}
  s' = b + (s-b)E,
  \qquad z' = zE,
  \label{eq:edge-asymmetry}
\end{equation}
where $E$ is the realized taper and $b$ is a science-derived background
level.  Realizations receive no $b(1-E)$ term.  Thus the preprocessing is not
one identical linear $F$ when $b\ne0$.  This report does not audit the filter
or choose a repair; it proposes a conditioned handoff to \path{SCI-FLT-001}.
