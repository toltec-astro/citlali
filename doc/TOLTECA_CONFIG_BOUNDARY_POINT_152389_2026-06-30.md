## Implications For Config Simplification

For this workflow, Citlali config simplification should start at the TolTECA
authoring layer, specifically the `reduce.steps.0.config.low_level` block in
`70_reduce.yaml`.

The safe migration shape is:

1. Keep the generated legacy Citlali low-level YAML valid.
2. Shorten the TolTECA-authored low-level block or introduce a compact profile
   that expands to the same legacy low-level YAML.
3. Treat `inputs` and `runtime.output_dir` as TolTECA-owned assembly products,
   not knobs that Citlali should expect users to author directly in this
   workflow.
4. Keep `72_reduce.yaml` focused on input/calibration selection unless a
   specific validation case needs low-level overrides.

This means the next behavior-preserving config work should be a TolTECA-facing
authoring layer prototype, not a removal of keys from Citlali's accepted
low-level schema.
