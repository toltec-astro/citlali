## Why this was redone
The previous attempt to add the new PCA mode triggered runtime instability (`std::bad_alloc`, then segfault path), and we reverted to recover a known-good pipeline.  
This pass reintroduces the new PCA mode in a constrained way:
1. Keep changes localized to processed-time-chunk cleaning (PTC).
2. Add explicit memory guards (`max_samples`, `max_modes`, detector filtering).
3. Ensure the legacy cut path is bypassed when the new mode is enabled.
4. Keep behavior unchanged when new mode is disabled.

## Functional goal
Add a brute-force null-model mode selector for PCA cleaning:
- Estimate how many correlated modes to remove (`k`) by comparing observed eigenvalues to a surrogate null envelope.
- Surrogates are generated by random circular time shifts per detector.
- This avoids fixed `n_eig_to_cut` and avoids using `stddev_limit` as the primary selector when enabled.

## Detailed implementation notes

### 1) `clean.h`

#### New configuration object
Added `Cleaner::NullModelOptions` with:
- `enabled`
- `n_surrogates`
- `quantile`
- `min_good_frac`
- `max_modes`
- `max_samples`
- `seed`

#### New helper routines
- `calc_cov_with_mask(sig, good)`:
  - Computes covariance with elementwise masking.
  - Uses safe denominator handling (`denom > 0`).
- `enforce_monotonic_nonincreasing(in)`:
  - Enforces non-increasing null envelope vs mode index.
  - Prevents pathological quantile shape from creating oscillatory `k`.

#### New selector
- `get_null_model_index(scans, flags, apt_flags)`:
  - Returns `k_null` (number of modes to remove).
  - Main steps:
    1. Fast exits if disabled/insufficient data.
    2. Time subsampling via `sample_step` to respect `max_samples`.
    3. Detector prefilter:
       - keep only `apt_flag == 0`
       - require unflagged-sample fraction `>= min_good_frac`
    4. Standardize each retained detector using unflagged samples.
    5. Compute observed eigenspectrum.
    6. Build surrogate eigenspectra (`n_surrogates`) via circular shifts.
    7. Compute per-mode null quantile (`quantile`), enforce monotonic envelope.
    8. `k_null = count(obs_eval > null_quantile)`, clamped.
  - Safety:
    - catches `std::bad_alloc` and generic exceptions
    - on failure logs warning and returns `0` (no forced cut)

#### Spectra solve-depth changes
In `calc_eig_values<SpectraBackend>`:
- If `null_model.enabled`, solve depth is controlled by `max_modes` (or full `n_dets-1` when `max_modes==0`).
- Adds guards for invalid `n_ev` / `n_cv` combinations.
- Adds safe early return when `n_ev <= 0`.
- Keeps legacy behavior when `null_model.enabled == false`.

#### Cut application changes
`remove_eig_values(...)` signature now accepts `forced_limit_index`.
- If `forced_limit_index >= 0`, it overrides legacy selection.
- Else old logic applies (`stddev_limit` or fixed `n_eig_to_cut`).
- Added clamping of `limit_index` to valid bounds.

### 2) `ptcproc.h`

#### Config parsing
Parses optional:
- `clean.null_model.enabled`
- `clean.null_model.n_surrogates`
- `clean.null_model.quantile`
- `clean.null_model.min_good_frac`
- `clean.null_model.max_modes`
- `clean.null_model.max_samples`
- `clean.null_model.seed`

Logs one summary line when enabled:
- `"clean.null_model enabled: ..."`

#### Runtime wiring
Inside the clean loop:
1. Still computes eigenpairs once for each group block.
2. If null-model enabled, computes `forced_limit_index = get_null_model_index(...)`.
3. Passes `forced_limit_index` into:
   - signal cleaning
   - kernel cleaning (if present)

This is the switch-off behavior for legacy selection: when forced index is provided, stddev/fixed-cut selection is bypassed.

## Runtime behavior matrix

### `null_model.enabled: false`
- Existing behavior remains:
  - choose cut via `stddev_limit` if active, else fixed `n_eig_to_cut`.
- No null-model computation path used.

### `null_model.enabled: true`
- Null model computes `k`.
- That `k` is used as `forced_limit_index`.
- Legacy cut-selection path is bypassed for deciding `limit_index`.
- Existing eigensolver still runs for cleaned projection basis; depth controlled by `max_modes` in this mode.

## Practical config guidance for your 70_reduce.yaml

The section you drafted is structurally consistent with this implementation.

Recommended initial values (close to your current):
```yaml
clean:
  enabled: true
  grouping: [nw]
  stddev_limit: 0
  n_eig_to_cut:
    a1100: [10]
    a1400: [10]
    a2000: [10]
  n_calc: 0
  null_model:
    enabled: true
    n_surrogates: 16
    quantile: 0.98
    min_good_frac: 0.8
    max_samples: 20000
    max_modes: 64
    seed: 12345
```

Notes:
- `n_eig_to_cut` becomes fallback only; forced null-model `k` should dominate when null model succeeds.
- `n_calc: 0` means no eval/evec output is stored; if you need diagnostics written, set `n_calc > 0`.
- If runtime or memory pressure appears, first reduce:
  - `max_samples` (e.g. `20000 -> 10000`)
  - then `max_modes` (e.g. `64 -> 32`)
